# Mini NPU Simulator

Python의 반복문만 사용해 입력 패턴과 필터 사이의 MAC(Multiply-Accumulate) 점수를 계산하고, 더 높은 점수를 얻은 필터를 기준으로 패턴을 판별하는 콘솔 프로그램입니다.

이 프로젝트는 다음 두 가지 실행 모드를 제공합니다.

1. 사용자가 직접 입력한 3×3 필터와 패턴 분석
2. `data.json`에 저장된 5×5, 13×13, 25×25 필터와 패턴 일괄 분석

---

## 1. 구현 범위

### 구현한 기능

- n×n 숫자 행렬을 2차원 리스트로 저장
- 3×3 사용자 입력 및 입력값 검증
- `data.json` 파일 읽기 및 최상위 스키마 검증
- `size_N_idx` 형식의 패턴 키에서 크기 `N` 추출
- 패턴과 필터의 행·열 크기 및 숫자 데이터 검증
- 필터 및 정답 라벨을 `Cross`, `X`로 정규화
- 외부 라이브러리 없이 이중 반복문으로 MAC 점수 계산
- `epsilon`을 적용한 부동소수점 점수 비교
- 동점일 때 `UNDECIDED` 판정
- JSON 케이스별 `PASS`/`FAIL` 처리
- 실패한 케이스의 식별자와 원인 출력
- 크기별 MAC 연산 시간 반복 측정 및 평균 계산
- 전체 테스트 수, 통과 수, 실패 수 요약 출력

## 5. 모드 1: 사용자 입력 3×3 분석

### 실행 흐름

1. 필터 A를 세 줄로 입력합니다.
2. 필터 B를 세 줄로 입력합니다.
3. 저장된 두 필터를 확인합니다.
4. 분석할 패턴을 세 줄로 입력합니다.
5. 필터 A와 패턴의 MAC 점수를 계산합니다.
6. 필터 B와 패턴의 MAC 점수를 계산합니다.
7. 두 점수를 비교해 `A`, `B`, 또는 `판정 불가`를 출력합니다.
8. 3×3 MAC 연산의 평균 실행 시간을 출력합니다.

각 행은 공백으로 구분된 숫자 3개로 입력해야 합니다. 정수와 실수를 모두 입력할 수 있습니다.

### 기본 정상 입력 예시

필터 A — Cross:

```text
0 1 0
1 1 1
0 1 0
```

필터 B — X:

```text
1 0 1
0 1 0
1 0 1
```

패턴 — X:

```text
1 0 1
0 1 0
1 0 1
```

이 입력에서는 계산 원리에 따라 필터 B의 점수가 더 높아야 합니다. 실제 콘솔 출력은 아래 테스트 기록에 직접 작성합니다.

### 사용자 입력 검증

다음 입력은 오류로 처리하고 같은 행을 다시 입력받습니다.

- 한 행에 입력한 숫자가 3개보다 적거나 많은 경우
- 숫자로 변환할 수 없는 문자가 포함된 경우
- 빈 줄을 입력한 경우

행 하나가 잘못되더라도 앞에서 정상적으로 입력한 행은 유지되며, 잘못 입력한 현재 행만 다시 입력합니다.

## 6. 모드 2: `data.json` 일괄 분석

### 실행 흐름

1. `main.py`와 같은 위치의 `data.json`을 읽습니다.
2. `filters`와 `patterns` 구조를 확인합니다.
3. 5×5, 13×13, 25×25 필터를 크기별로 검증합니다.
4. 각 패턴 키에서 크기 `N`을 추출합니다.
5. 패턴의 `input`과 `expected` 값을 검증합니다.
6. 해당 크기의 Cross 필터와 X 필터를 선택합니다.
7. 두 필터의 MAC 점수를 계산합니다.
8. `epsilon` 정책으로 최종 판정을 결정합니다.
9. 판정 결과와 정답 라벨을 비교해 `PASS` 또는 `FAIL`을 출력합니다.
10. 크기별 성능 분석과 전체 결과 요약을 출력합니다.

### 필요한 JSON 구조

아래는 구조를 설명하기 위한 예시이며, 문자열로 표시된 행렬 부분을 실제 n×n 숫자 배열로 바꿔야 합니다.

```json
{
  "filters": {
    "size_5": {
      "cross": "5x5 숫자 배열",
      "x": "5x5 숫자 배열"
    },
    "size_13": {
      "cross": "13x13 숫자 배열",
      "x": "13x13 숫자 배열"
    },
    "size_25": {
      "cross": "25x25 숫자 배열",
      "x": "25x25 숫자 배열"
    }
  },
  "patterns": {
    "size_5_1": {
      "input": "5x5 숫자 배열",
      "expected": "+"
    },
    "size_13_1": {
      "input": "13x13 숫자 배열",
      "expected": "x"
    }
  }
}
```

### 패턴 키 규칙

패턴 키는 반드시 다음 형식을 사용해야 합니다.

```text
size_N_idx
```

예시:

```text
size_5_1
size_13_2
size_25_3
```

- `N`은 패턴과 필터의 한 변 크기입니다.
- `idx`는 같은 크기 안에서 케이스를 구분하는 양의 정수입니다.
- 크기와 번호는 모두 0보다 큰 정수여야 합니다.
- 프로그램은 키에서 추출한 `N`으로 `size_N` 필터를 선택합니다.

## 7. 핵심 구현 설명

### 7.1 MAC 연산

패턴과 필터의 같은 위치에 있는 값을 곱하고 모든 결과를 누적해 하나의 점수로 만듭니다.

```text
score = Σ(pattern[row][col] × filter[row][col])
```

구현에서는 NumPy 같은 외부 라이브러리를 사용하지 않고 행과 열을 순회하는 이중 반복문을 사용합니다.

예를 들어 3×3 입력 한 개와 필터 한 개를 비교하면 총 9개 위치에서 곱셈과 누적 덧셈이 수행됩니다.

### 7.2 라벨 정규화

JSON 데이터의 원본 라벨 표기가 서로 달라도 프로그램 내부에서는 다음 두 표준 라벨만 사용합니다.

| 원본 라벨 | 표준 라벨 |
|---|---|
| `+` | `Cross` |
| `cross` | `Cross` |
| `x` | `X` |

라벨을 비교하기 전에는 앞뒤 공백을 제거하고 소문자로 변환합니다. 정규화할 수 없는 라벨은 해당 케이스의 실패 원인으로 기록됩니다.

### 7.3 부동소수점과 동점 처리

프로그램의 허용오차는 다음과 같습니다.

```python
EPSILON = 1e-9
```

두 점수의 차이가 다음 조건을 만족하면 동점으로 처리합니다.

```python
abs(cross_score - x_score) < EPSILON
```

- JSON 분석 모드의 동점 판정: `UNDECIDED`
- 사용자 입력 모드의 동점 표시: `판정 불가`

부동소수점 계산에서는 수학적으로 같아야 하는 값도 메모리 표현 방식 때문에 아주 작은 차이가 발생할 수 있습니다. 따라서 두 값을 `==`로 직접 비교하지 않고 허용오차 이내인지 확인합니다.

### 7.4 행렬 검증

행렬은 다음 조건을 모두 만족해야 합니다.

- 전체 데이터가 리스트일 것
- 행 개수가 예상 크기 `N`과 같을 것
- 각 행이 리스트일 것
- 각 행의 열 개수가 `N`과 같을 것
- 모든 요소가 `int` 또는 `float`일 것
- Python에서 `bool`이 `int`의 하위 자료형으로 취급되는 점을 고려해 `True`, `False`는 숫자로 인정하지 않을 것

### 7.5 JSON 오류 처리

파일을 읽는 과정에서는 다음 오류를 안내합니다.

- `data.json` 파일을 찾을 수 없음
- JSON 문법 오류
- 운영체제 수준의 파일 읽기 오류
- JSON 최상위 값이 객체가 아님

개별 패턴의 키, 입력 행렬, 정답 라벨 또는 필터에 문제가 있으면 프로그램 전체를 비정상 종료하지 않고 해당 케이스를 `FAIL`로 기록한 뒤 가능한 다음 케이스 분석을 계속합니다.

### 7.6 성능 측정

성능 측정은 다음 방식으로 수행합니다.

- 각 크기에서 최소 10회 반복
- Cross와 X 필터를 각각 측정
- 최초 실행의 영향을 줄이기 위한 준비 실행 수행
- `time.perf_counter_ns()`로 연산 함수 호출 구간 측정
- 전체 측정 시간을 실제 MAC 함수 호출 횟수로 나누어 호출 1회당 평균 시간 계산
- 파일 읽기와 콘솔 출력 시간은 측정 구간에서 제외

```

0 0 0
```

패턴:

```text
1 0 0
0 0 0
0 0 0
```

### 9.3 실패 원인 분석

1. 프로그램은 원본 라벨을 바로 비교하지 않고 `Cross`와 `X`로 정규화한 뒤 비교한다. 따라서 `+`, `cross`, `x`처럼 표기가 다른 데이터 때문에 정상 케이스가 잘못 실패하는 문제를 줄일 수 있다.
2. 정규화할 수 없는 라벨이 들어오면 임의로 Cross 또는 X라고 추측하지 않고 해당 케이스를 `FAIL`로 기록한다. 이 실패는 MAC 계산 로직보다 데이터 라벨 또는 스키마 문제로 분류할 수 있다.
3. 패턴 키가 `size_N_idx` 규칙을 따르지 않으면 크기별 필터를 올바르게 선택할 수 없다. 이 경우에도 점수 계산을 시도하지 않고 키 형식 오류를 실패 사유로 남긴다.
4. 패턴과 필터의 행 또는 열 개수가 키에서 추출한 크기 `N`과 다르면 같은 위치끼리 안전하게 곱할 수 없다. 이 문제는 판정 로직이 아니라 입력 데이터의 크기 불일치 문제다.
5. `input`이나 `expected`가 누락된 케이스는 분석에 필요한 필수 정보가 없으므로 `FAIL` 처리된다. 프로그램은 오류가 발생한 한 케이스 때문에 전체 실행이 중단되지 않도록 결과에 원인을 저장하고 반환한다.
6. 행렬 안에 문자열이나 불리언 값이 들어오면 숫자 MAC 연산의 입력 조건을 만족하지 않는다. 특히 Python에서 `bool`은 `int`의 하위 자료형이므로 별도 검사를 통해 숫자 데이터에서 제외한다.
7. 부동소수점 점수를 `==`로 직접 비교하면 표현 오차 때문에 사실상 같은 점수가 서로 다른 것으로 판단될 수 있다. 이를 방지하기 위해 두 점수의 차이가 `1e-9` 미만이면 `UNDECIDED`로 처리한다.
8. `UNDECIDED`는 Cross 또는 X 중 하나를 억지로 선택하지 않는 안전한 비교 정책이다. JSON의 기대 라벨이 Cross 또는 X인데 실제 판정이 `UNDECIDED`라면 정책상 `FAIL`이 되며, 실패 사유에는 두 점수 차이가 허용오차 미만이라는 내용이 기록된다.
9. 허용오차 경계는 `< 1e-9`이다. 따라서 점수 차이가 정확히 `1e-9`인 경우에는 동점이 아니며 더 큰 점수의 라벨로 판정된다. 경계값 테스트에서는 이 조건을 구분해서 확인해야 한다.

## 10. 시간 복잡도 분석

### 10.1 MAC 함수

n×n 패턴과 n×n 필터를 비교할 때 모든 행과 열을 한 번씩 방문합니다.

```text
행 반복 횟수: N
열 반복 횟수: N
전체 위치 수: N × N = N²
```

따라서 필터 한 개와 패턴 한 개의 MAC 점수를 계산하는 시간 복잡도는 다음과 같습니다.

```text
O(N²)
```

추가로 사용하는 변수는 누적 점수와 반복문의 인덱스 정도이므로, 입력 행렬을 제외한 MAC 함수 자체의 추가 공간 복잡도는 다음과 같습니다.

```text
O(1)
```

### 10.2 두 필터 비교

패턴 하나를 Cross 필터와 X 필터에 각각 비교하므로 실제 위치 연산 수는 대략 다음과 같습니다.

```text
2 × N²
```

상수 2는 빅오 표기에서 제거되므로 전체 판정의 시간 복잡도 역시 `O(N²)`입니다.

### 10.3 반복 성능 측정

반복 횟수를 `R`, 필터 개수를 `F`, 행렬의 한 변 크기를 `N`이라고 하면 성능 측정의 전체 시간 복잡도는 다음과 같습니다.

```text
O(R × F × N²)
```

현재 기본 설정에서는 `R = 10`, `F = 2`입니다. 두 값은 고정된 상수이므로 크기 증가 관점에서는 여전히 `O(N²)`로 볼 수 있습니다.

### 10.4 크기별 연산량

| 크기 | 위치 연산 수 `N²` | 3×3 대비 위치 수 |
|---:|---:|---:|
| 3×3 | 9 | 약 1.00배 |
| 5×5 | 25 | 약 2.78배 |
| 13×13 | 169 | 약 18.78배 |
| 25×25 | 625 | 약 69.44배 |

이론적으로 `N`이 두 배가 되면 처리할 위치 수는 약 네 배가 됩니다. 예를 들어 한 변 길이가 5에서 10으로 두 배가 된다면 위치 수는 25에서 100으로 네 배가 됩니다. 이것이 MAC 반복문의 시간 복잡도가 `O(N²)`인 근거입니다.

실제 측정 시간은 이론적인 연산량과 완전히 같은 비율로 증가하지 않을 수 있습니다. Python 반복문 비용, 함수 호출 비용, CPU 캐시, 운영체제 스케줄링과 같은 고정 비용과 실행 환경의 영향을 함께 받기 때문입니다. 따라서 성능 표에서는 절대 시간뿐 아니라 `N²`의 증가와 전체적인 시간 증가 경향을 함께 해석해야 합니다.

### 실제 측정값 해석

> `3×3, 5×5, 13×13, 25×25의 평균 측정 시간은 각각 0.001013 ms, 0.001970 ms, 0.010777 ms, 0.031247 ms였다. 크기가 커질수록 N² 위치 연산 수가 9, 25, 169, 625로 증가했고, 측정 시간은 전반적으로 증가하는 경향을 보였다. 일부 크기에서 이론적인 비율과 차이가 난 이유는 Python 반복문과 함수 호출의 고정 비용, CPU 캐시, 운영체제 스케줄링 및 타이머 해상도의 영향으로 해석했다. 전체적으로 측정 결과는 O(N²) 시간 복잡도와 전반적으로 일치했다.`
